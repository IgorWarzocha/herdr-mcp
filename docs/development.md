# Bridge boundaries

Run `npm ci` to install dependencies and `npm run check` for syntax checks and tests. Tests use temporary files and isolated HTTP listeners. They must not use a deployed bridge, real token or tunnel.

`npm run check:long-wait` is a separate 65-second smoke check through the real HTTP and MCP SDK transport. It uses a harmless Node subprocess instead of Herdr and verifies keepalives plus completion beyond both the ordinary 25-second limit and the SDK's default 60 seconds. It does not establish hosted-client deadlines.

Before every restart, run `npm run check:live` with the service's installed Herdr binary and PATH. It exercises every friendly verb through the real MCP transport in a disposable named Herdr session, including agent and shell sends. It starts the installed Pi with an isolated config, Herdr's installed integration and a synthetic saved conversation. Only a local `/name` command is submitted, so no model credentials or inference calls are needed. The temporary session, files and processes are removed on exit. A failure blocks deployment. The gate needs both Herdr and Pi on PATH.

`scripts/protocol-smoke.mjs` checks 2025-03-26 and 2025-06-18 initialization, exact negotiated versions and subsequent tool calls, plus 2026-07-28 discovery. Both the pre-restart live gate and the post-restart connection check run it. The client revision cases are independent of the server's supported-version list so accidentally removing a client fails deployment.

`npm run restart` reads the Linux service's effective settings from systemd and runs the gate in a transient unit with the same launcher, environment files and working directory. It rejects a different checkout or an unverifiable command before stopping the bridge. After restarting, it verifies the local connection under the same service settings. `node scripts/restart.mjs --check` runs only the manager-configured gate. For macOS or another supervisor, run `check:live` with that supervisor's actual environment before stopping the old process. Automatic gated restart is Linux-only. `npm run check:connection` performs read-only authenticated discovery against the local endpoint, or `HERDR_MCP_URL` when set. It loads the existing token privately and prints no pane contents. The selected hosted client still needs its own setup check.

The MCP surface has two tools: `herdr_skill` reads the installed CLI guide, and `herdr` passes validated arguments to the pinned local Herdr server. `src/friendly.mjs` resolves friendly targets from a fresh directory, rejects ambiguity and selects agent or shell operations. Shell sends require an available foreground shell. Agent sends are never retried as shell commands after failure. Friendly `list` projects one `api snapshot` into a directory of panes with their UI labels. Raw CLI commands remain unchanged. The bridge launches Herdr without a shell. A shell-targeted send deliberately submits a command to the destination shell.

`src/http.mjs` owns HTTP authentication and budgets around SDK v2's `createMcpHandler` and Node adapter. `src/mcp.mjs` registers the tools and resource on the low-level SDK `Server` so invalid tool inputs retain the bridge's short error envelope. The SDK negotiates 2025-03-26 and 2025-06-18 through its stateless `initialize` path. MCP 2026-07-28 uses the SDK's modern discovery path. Only modern clients are offered subscriptions. The SDK owns protocol encoding, acknowledgements, filtering and cancellation; the bridge does not handcraft initialization responses. The current-Herdr requirement is unchanged.

`src/reply.mjs` reads only the Pi session path reported for the resolved live pane. It accepts the current version-3 session format, scans complete JSONL records backwards and follows parent IDs from the last persisted leaf. It returns completed assistant text blocks with `stopReason: stop`, excluding reasoning and tools. Reads are bounded to 16 MiB scanned and 4 MiB per record. Unicode-character pagination bounds the response. A live branch switch without a persisted record cannot be recovered from the file, so the result explicitly names the last persisted branch and marks newer user or assistant activity.

`src/directory.mjs` joins snapshot identities and bounds the projected directory. `src/pane-updates.mjs` owns one lazy observer shared by subscriptions, its cache, cancellation and generation checks. It reads a snapshot every two seconds after the previous read completes, only while the SDK event bus has subscribers. Removing the last subscriber aborts the active observation and clears the cache. A changed directory or failure publishes a resource invalidation. No terminal transcript is sampled. [Push clients](push.md) documents the public resource and receiving client.

The bridge fixes the session through `HERDR_MCP_SOCKET` or `HERDR_SOCKET_PATH`. It rejects session and machine routing, maintenance commands, bare TUI launch and API schema file output. These guards are not a sandbox. A token holder can still execute shell commands through a pane.

The subprocess environment excludes caller pane identity and secrets. Windows keeps the loader and profile variables needed to launch a native executable. Token content is validated on every OS. POSIX also enforces private mode bits and ownership. Native Windows ACLs remain the operator's responsibility.

## Results and timeouts

`src/errors.mjs` owns the public `code`, `message` and `next` recovery envelope. Known CLI errors are classified from Herdr's stderr JSON `error.code`, only on failure. Successful terminal text must never be interpreted as a bridge error. Unknown diagnostics and exception messages are not sent to clients. Existing exit, signal, timeout and truncation fields remain available. Partial successful output survives truncation. Failed-command diagnostic streams are replaced with the short message, not a backtrace.

Ordinary subprocesses have a 25-second watchdog. Only `agent wait` and `pane wait-output`, including the friendly `wait` alias, get the longer budget. `HERDR_MCP_WAIT_MAX` is a positive integer in milliseconds, default 90000. Longer ceilings remain available for clients that support them. The CLI's requested `--timeout` is capped there. A watchdog allows another two seconds for CLI cleanup, and an expired wait can take up to two more seconds to fetch current agent state. A failed state probe is explicit, never interpreted as working or complete. `agent prompt --wait` and raw `api` calls retain the ordinary limit because they can include mutations.

Calls are bounded to 128 KiB combined output and four subprocesses. The directory observer shares those subprocess slots with tools. HTTP accepts at most 128 KiB per body, 16 active requests, eight subscriptions and 64 connections. The subscription cap leaves request capacity for tools and reads. The Node request and header timeouts bound receiving a request, not waiting for its response. Tool responses and subscription streams use the SDK's Streamable HTTP SSE mode with its supported 15-second keepalive setting. No SDK code is patched. Client hard deadlines still apply, including the TypeScript SDK's default 60 seconds. See [client setup](clients.md#verify-discovery-and-long-waits).

When the HTTP client disconnects, the response's close event aborts the command signal. The runner terminates the wait subprocess and releases its slot. This cancels the observation, not the agent working in the pane. If a client or proxy reports a timeout without closing its connection to the bridge, the bridge's own deadline still bounds the wait.

Cancelling or timing out a call does not roll back input already sent to a pane. No transcript or durable notification queue is kept. Do not retry a mutation merely to retrieve lost output.
