# Bridge boundaries

Run `npm ci` to install dependencies and `npm run check` for syntax checks and tests. Tests use temporary files and isolated HTTP listeners. They must not use a deployed bridge, real token or tunnel.

`npm run check:long-wait` is a separate 65-second smoke check through the real HTTP and MCP SDK transport. It uses a harmless Node subprocess instead of Herdr and verifies keepalives plus completion beyond both the ordinary 25-second limit and the SDK's default 60 seconds. It does not establish hosted-client deadlines.

Before every restart, run `npm run check:live` with the service's runtime binaries and PATH. It exercises the unified verbs through the real MCP transport. TUI uses a disposable named session, installed Pi, an isolated config, Herdr's installed integration and a synthetic saved conversation. Only a local `/name` command is submitted. Core uses a private session and a Node OSC-status fixture, not an installed agent or a model call. Temporary sessions, files and processes are removed on exit. A failure blocks deployment. Both installed runtimes must pass. TUI checks need Pi on PATH. Core-only checks do not.

`scripts/protocol-smoke.mjs` checks 2025-03-26 and 2025-06-18 initialization, exact negotiated versions and subsequent tool calls, plus 2026-07-28 discovery. Both the pre-restart live gate and the post-restart connection check run it. The client revision cases are independent of the server's supported-version list so accidentally removing a client fails deployment.

`npm run restart` reads the Linux service's effective settings from systemd and runs the gate in a transient unit with the same launcher, environment files and working directory. It rejects a different checkout or an unverifiable command before stopping the bridge. After restarting, it verifies the local connection under the same service settings. `node scripts/restart.mjs --check` runs only the manager-configured gate. For macOS or another supervisor, run `check:live` with that supervisor's actual environment before stopping the old process. Automatic gated restart is Linux-only. `npm run check:connection` performs read-only authenticated discovery against the local endpoint, or `HERDR_MCP_URL` when set. It loads the existing token privately and prints no pane contents. The selected hosted client still needs its own setup check.

The MCP surface retains two tools: `herdr_skill` returns `RUNTIME_GUIDE`, the unified bridge guide in `src/runtimes.mjs`, and `herdr` retains its `args` or `command` input and routes validated commands to pinned local runtimes. Startup requires at least one installed binary: Herdr TUI 0.9.5+ or Core `hc` 0.1.14+. Missing default binaries are optional. Explicitly configured missing binaries, broken probes and unsupported installed versions fail startup. The Node floor is unchanged.

`src/runtimes.mjs` merges directories and owns cross-runtime identity, unique-label resolution and the `list`, `get`, `read`, `send`, `wait`, `reply`, `close` and `spawn` verbs. TUI IDs stay unchanged. Core IDs are `core:tN`. A known Core ID addresses a retained terminal directly without a directory query, including after exit. Partial directories report `unavailable`. Names fail closed when either backend is unavailable, while explicit IDs stay on their owning runtime. New programs prefer Core when installed. A failed mutation is never retried on another runtime. Without Core, spawn creates a TUI workspace and starts a supported agent, not an arbitrary program.

`src/core.mjs` adapts Core JSON responses without guessing status. Core reads mark incomplete output. Core waits without reported status wait for process exit, and output matches observe only output after the wait begins. Regular expressions remain TUI-only. Core `ls` may contact configured remote machines. The adapter filters remote rows and permits only local terminal IDs for mutations.

For TUI, `src/friendly.mjs` resolves friendly targets from a fresh directory, rejects ambiguity and selects agent or shell operations. Shell sends require an available foreground shell. Agent sends are never retried as shell commands after failure. Friendly `list` projects one `api snapshot` into a directory of panes with their UI labels. Raw TUI commands outside the unified verbs retain CLI syntax. There is no raw Core pass-through. The bridge launches Herdr without a shell. A shell-targeted send deliberately submits a command to the destination shell.

`src/http.mjs` owns HTTP authentication and budgets around SDK v2's `createMcpHandler` and Node adapter. `src/mcp.mjs` registers the tools and resource on the low-level SDK `Server` so invalid tool inputs retain the bridge's short error envelope. The SDK negotiates 2025-03-26 and 2025-06-18 through its stateless `initialize` path. MCP 2026-07-28 uses the SDK's modern discovery path. Only modern clients are offered subscriptions. The SDK owns protocol encoding, acknowledgements, filtering and cancellation; the bridge does not handcraft initialization responses. Runtime version requirements do not narrow the supported MCP client revisions.

`src/reply.mjs` reads only the Pi session path reported for the resolved target. Core requires `status.app: pi` and `labels['pi.session_file']` from `get`. Our Pi integration supplies that label, not Core itself. The bridge never scans directories to discover sessions. It accepts the current version-3 session format, scans complete JSONL records backwards and follows parent IDs from the last persisted leaf. It returns completed assistant text blocks with `stopReason: stop`, excluding reasoning and tools. Reads are bounded to 16 MiB scanned and 4 MiB per record. Unicode-character pagination bounds the response. A live branch switch without a persisted record cannot be recovered from the file, so the result explicitly names the last persisted branch and marks newer user or assistant activity.

`src/directory.mjs` joins snapshot identities and bounds the projected directory. `src/pane-updates.mjs` owns one lazy observer shared by subscriptions, its cache, cancellation and generation checks. It reads the merged runtime directory every two seconds after the previous read completes, only while the SDK event bus has subscribers. Removing the last subscriber aborts the active observation and clears the cache. A changed directory or failure publishes a resource invalidation. No terminal transcript is sampled. [Push clients](push.md) documents the public resource and receiving client.

The bridge pins TUI through `HERDR_MCP_SOCKET` or `HERDR_SOCKET_PATH`. Core is auto-detected through `hc` on the service PATH, or selected by `HERDR_MCP_CORE_BINARY`. `HERDR_MCP_CORE_SOCKET` sets an optional absolute socket path and `HERDR_MCP_CORE_SESSION` defaults to `default`. It rejects session and machine routing, maintenance commands, bare TUI launch and API schema file output. These guards are not a sandbox. A token holder can still execute shell commands through a pane.

The subprocess environment excludes caller pane identity and secrets, including inherited `HC_SESSION`, `HC_SOCKET` and `HC_TERMINAL_ID`. Only the bridge's pinned Core settings are passed. Windows keeps the loader and profile variables needed to launch a native executable. Token content is validated on every OS. POSIX also enforces private mode bits and ownership. Native Windows ACLs remain the operator's responsibility.

## Results and timeouts

`src/errors.mjs` owns the public `code`, `message` and `next` recovery envelope. Known CLI errors are classified only on failure, using TUI stderr JSON `error.code` or Core `error.kind`. Successful terminal text must never be interpreted as a bridge error. Unknown diagnostics and exception messages are not sent to clients. Existing exit, signal, timeout and truncation fields remain available. Partial successful output survives truncation. Failed-command diagnostic streams are replaced with the short message, not a backtrace.

Ordinary subprocesses have a 25-second watchdog. Only unified `wait` and the TUI `agent wait` and `pane wait-output` forms get the longer budget. `HERDR_MCP_WAIT_MAX` is a positive integer in milliseconds, default 90000. Longer ceilings remain available for clients that support them. The CLI's requested `--timeout` is capped there. A watchdog allows another two seconds for CLI cleanup, and an expired wait can take up to two more seconds to fetch current agent state. A failed state probe is explicit, never interpreted as working or complete. `agent prompt --wait` and raw `api` calls retain the ordinary limit because they can include mutations.

Calls are bounded to 128 KiB combined output and four subprocesses. The directory observer shares those subprocess slots with tools. HTTP accepts at most 128 KiB per body, 16 active requests, eight subscriptions and 64 connections. The subscription cap leaves request capacity for tools and reads. The Node request and header timeouts bound receiving a request, not waiting for its response. Tool responses and subscription streams use the SDK's Streamable HTTP SSE mode with its supported 15-second keepalive setting. No SDK code is patched. Client hard deadlines still apply, including the TypeScript SDK's default 60 seconds. See [client setup](clients.md#verify-discovery-and-long-waits).

When the HTTP client disconnects, the response's close event aborts the command signal. The runner terminates the wait subprocess and releases its slot. This cancels the observation, not the agent working in the pane. If a client or proxy reports a timeout without closing its connection to the bridge, the bridge's own deadline still bounds the wait.

Cancelling or timing out a call does not roll back input already sent to a pane. No transcript or durable notification queue is kept. Do not retry a mutation merely to retrieve lost output.
